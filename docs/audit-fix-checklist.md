# 星云 AI 群聊（chat.20030212.xyz）修改清单

来源：2026-11-23 以「第一次打开网站的新用户」视角对线上站点做的完整体验审计。

执行说明：按 P0 → P1 → P2 的顺序逐项修改；每项包含【现象】【改法】【验收】，改完请按验收标准自测。文末「保持现状」列出的体验是审计验证过的好设计，不要在修改中弄丢。「待站长确认」的条目不要擅自改动。

## P0（阻碍新用户使用，优先改）

### 1. 没配 key 时聊天页零提示

【现象】新房间未设置全局 API key 时，用户在群里发消息，只有个别成员回一条「暂时没回上来」，其余成员沉默，聊天页没有任何解释。真正原因「还没设全局 key，成员们不会回复」只写在「我 → 接口设置」页里。

【改法】①进入群聊时若全局 key 为空，在聊天区顶部显示常驻提示条：「先设置接口 key，成员们才能回复」并带跳转到接口设置的按钮。②未配 key 时用户发消息，不再走成员回复流程、不再产生「暂时没回上来」，改为插入一条系统消息说明原因并附设置入口。

【验收】新建房间、不填 key、发任意消息：立即看到明确提示和入口，无任何成员的假失败回复。

### 2. 产品名称混乱

【现象】顶栏叫「AI 群聊」、默认群名叫「星云 AI 群聊」、群公告写「接口由星云智联API 提供」、底部导航第一项叫「微信」，四个名字并存，新用户以为打开了微信。

【改法】全站统一使用一个产品名（建议「星云 AI 群聊」）；底部导航第一项由「微信」改为「群聊」；接口提供方信息只保留在接口设置页或页脚一处。

【验收】全站界面不再出现以「微信」命名的导航或标题，产品名只有一种写法。

### 3. 「活人感」开关与实际行为不符

【现象】聊天设置里「活人感」处于关闭状态时，成员仍会在用户发表情、成员彼此发言后自发接话多轮。开关说明写的是「没被 @ 时成员自己决定要不要插话」，与实际表现对不上。

【改法】先定位自发接话的触发逻辑：若自发接话本应受该开关控制，修复为关闭时不触发；若自发接话是另一套独立机制（例如成员互评接话），则修改开关的说明文案，把两者各自管什么写清楚。

【验收】开关关闭时，除被 @ 和被直接提问外成员不主动发言；或者开关说明与实际行为完全一致，二者取其一并自测通过。

### 4. 等待回复时反馈不足

【现象】「流式输出」默认关闭；关闭时发完消息只能干等。开启时「XX 正在回复中…」和逐字效果也很短暂，不盯着看就感觉不到。

【改法】①流式输出默认改为开启。②无论流式是否开启，成员生成期间持续显示「XX 正在回复中…」，直到该成员的回复真正落到聊天里再消失。

【验收】发一条全群问题：从发送到回复出现之间，能持续看到正在回复的提示。

## P1（高频使用中的别扭点）

### 5. 两处状态刷新滞后

【现象】①群设置里点「全员同一个模型」成功并弹提示后，下方成员列表仍显示旧模型，退出重进才更新。②接口设置保存 key 成功后，回到「我」页，「接口设置」一行仍显示「还没设 key」，逛一圈回来才变。

【改法】写操作成功后，同步刷新所有受影响视图的本地状态，不要等重新进入页面才拉新数据。

【验收】上述两处操作完成后，当前页面立即显示新状态，无需退出重进。

### 6. 人设要逐个保存

【现象】群设置「谁扮演谁（本群人设）」里每个成员一个人设框、一个「保存人设」按钮，7 个人要保存 7 次，漏点一个就白改。

【改法】在该区域底部增加「保存全部人设」按钮，一次提交所有改动，并给出统一的成功提示；单个保存按钮可保留。

【验收】修改 3 位成员的人设，点一次「保存全部」后重进页面，3 处修改都在。

### 7. 表情点即发送容易误发，且发送后输入框残留

【现象】表情面板里点任意表情会立即作为一条消息发出去（不是插入输入框），新手容易误触；发送后输入框里之前打好的 @ 提及还留着，容易接着误发。

【改法】保留点即发送也可以，但发送表情后要清掉输入框中已被消费的 @ 提及状态；或者改为点击先预览、再点发送。两种方案选一种，全站保持一致。

【验收】输入框里有 @ 某人时点一个表情：表情发出后，输入框状态干净、无残留误导。

### 8. 导出聊天记录无任何反馈

【现象】在发现页点「导出当前群聊天记录」后，页面没有任何提示，看不到下载，用户无法确认是否成功。

【改法】导出触发后给出明确反馈（toast「聊天记录已导出」或触发浏览器下载并提示文件名）；若导出失败也要给出失败提示。

【验收】点击导出后，用户能明确知道成功还是失败。

### 9. 房间码没有一键复制

【现象】「我的房间」页房间码只能手动选中复制。

【改法】房间码旁加「复制」按钮，点击后复制到剪贴板并 toast 提示「已复制」。

【验收】点一次即可复制成功。

### 10. 长页面返回不便

【现象】接口设置等长页面滚到底部后，返回入口只在页面顶部，要滚回去才能退出。

【改法】设置类长页面加吸顶（固定）的顶部返回栏，或底部加返回按钮。

【验收】滚到页面底部也能一键返回上一级。

### 11. 表情图片首次加载慢

【现象】表情包管理页首次打开，8 张猫咪贴纸位置空白数秒才陆续显示；原图单张约 0.8–1MB。

【改法】把 8 张内置贴纸图压缩为 webp（长边 ≤640px、单张目标 ≤80KB），并给图片位加加载占位（底色或骨架），避免长时间纯空白。

【验收】首次打开表情包管理页，图片在 1 秒内基本呈现，不再长时间空白。

## P2（体验打磨）

### 12. 桌面端大片留白、空状态页太秃

【现象】桌面宽屏下内容只有中间约 500px 窄栏，两侧大片浅灰留白；通讯录、我的收藏等空状态页只有一句话加留白。

【改法】桌面端（≥1024px）改两栏布局（左侧群列表/导航，右侧内容区）或适当放宽内容区；空状态页加一句引导文案和一个行动按钮（如通讯录空时给「去群里看看」）。

【验收】桌面打开各主页面，不再出现大面积无内容留白。

### 13. 术语对新用户不友好

【现象】界面出现「base」「lorebook」等英文术语；模型名里的「按次0.05」「按次0.08」没有解释计价含义。

【改法】「base」统一写作「接口地址（base）」；「lorebook」首次出现处加中文注「（世界书）」；在模型库区域加一行小字说明「按次 X = 每次调用约 X 元」这类计价标记的含义（按实际计费规则填写）。

【验收】没接触过这类工具的新用户能看懂上述三处。

### 14. 多人回复内容容易撞车

【现象】同一个问题下，多位成员举了完全相同的例子（审计中 3 人同时用「换工作」举例），重复感明显。

【改法】回复生成改为串行接龙：后回复的成员能看到前面成员已发出的回复再开口；或在成员的系统提示中明确要求「先看其他成员已说的内容，举例和角度不要重复」。两种方案选一种或叠加。

【验收】用「请每人说说自己最擅长什么，并举个小例子」测试：多人举例不再重复。

### 15. 没有帮助入口

【现象】「我」页底部只有退出房间、清空记录、删除房间等危险操作，没有任何帮助/说明入口；新用户遇到问题无处可查。

【改法】在「我」页增加「帮助 / 使用说明」入口，做一个简单说明页，至少覆盖：怎么设置接口 key、房间码是什么、「活人感」和「流式输出」分别是什么。

【验收】新用户两步之内能找到上述说明。

## 保持现状（审计验证过的好体验，修改时不要弄丢）

- 配好 key 后回复很快（7 人 30 秒内全部回复），且回复贴合各自人设、语言自然。
- @ 某个成员时只有 TA 回复，定向准确。
- 成员会围绕用户发的表情自发互动、互相引用，群聊氛围好（与第 3 项协调：目标是让开关名副其实，不是砍掉互动）。
- 微信式界面（绿底己方气泡、成员白底气泡、彩色单字头像）字号和气泡大小舒适，窄屏下无挤压错位。
- 接口设置页有「key 只保存在这台服务器上你自己的房间数据里」的安全说明，让人安心，保留。

## 待站长确认（不要擅自改动）

- 预设成员阵容里阿深的模型是 deepseek-v4.1-flash，默认群里阿深原是 deepseek-v4.1，两处不一致是否为有意设计，请站长确认。
